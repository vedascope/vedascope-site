# Управление мероприятиями vedascope

## Где лежат данные

Единый источник данных мероприятий: `data/events.json`.

Главная страница загружает этот файл и строит блок "Ближайшие события" из него. Если JSON не загрузится, используется резервный список из `assets/js/events.js`.

Отдельные страницы мероприятий лежат в `events/<slug>/index.html`.

Общая страница всех мероприятий: `events/index.html`.

## Обязательные поля

Для новой записи в `data/events.json` нужны:

- `id` - технический идентификатор.
- `slug` - адрес страницы на латинице.
- `title` - название.
- `subtitle` - короткое уточнение.
- `date`, `startDate`, `endDate`, `dateLabel` - дата для карточек и сортировки.
- `time` - время или "Время уточняется".
- `city`, `location`, `venue` - город, место, площадка.
- `format`, `formatLabel` - `online`, `offline` или `hybrid`.
- `short_description` и `description` - текст для карточек.
- `full_description` - массив абзацев для страницы мероприятия.
- `program` - массив пунктов программы.
- `speakers` - массив ведущих; если данных нет, можно оставить пустой массив.
- `price` - стоимость или "Уточняется".
- `cta_text`, `cta_url` - текст и ссылка основной кнопки.
- `status` - `upcoming`, `past` или `draft`.
- `featured` - `true`, если событие должно быть на главной.
- `image` - путь к фоновой картинке.
- `tags` - теги для фильтров.
- `links.details` - путь вида `events/<slug>/`.
- `calendarFile` - `.ics` файл, если есть.

## Как добавить новое мероприятие

1. Добавить объект в `data/events.json`.
2. Создать папку `events/<slug>/`.
3. Создать в ней `index.html` по структуре существующих страниц, например `events/seminar-july-2026/index.html`.
4. В `links.details` указать `events/<slug>/`.
5. Если мероприятие должно появиться на главной, поставить `featured: true`.
6. Если мероприятие пока не готово к публикации, поставить `status: draft` и не добавлять ссылку на страницу в публичные блоки.
7. Проверить `events/`.
8. Проверить блок "Ближайшие события" на главной.

## Как вывести или скрыть на главной

Главная берёт события из `data/events.json`.

Чтобы событие было обычным ближайшим событием:

- `status` должен быть `upcoming`;
- дата `endDate` должна быть актуальной;
- `links.details` должен вести на страницу мероприятия.

Чтобы скрыть прошедшее мероприятие:

- поменять `status` на `past`;
- оставить страницу в `events/<slug>/`, чтобы старые ссылки не ломались;
- при необходимости перенести карточку в блок прошедших на `events/index.html`.

## Как обновить общую страницу

`events/index.html` сейчас статическая. После изменения `data/events.json` нужно синхронизировать карточки на этой странице вручную или перегенерировать её по текущей структуре карточек.

Карточка должна показывать:

- дату;
- название;
- город и формат;
- краткое описание;
- статус;
- кнопку "Подробнее".

## Шаблон страницы мероприятия

За основу берите любую универсальную страницу:

- `events/moskva-konferentsiya-2026/index.html`
- `events/seminar-july-2026/index.html`
- `events/jyotish-practice-august-2026/index.html`

Страница должна сохранять блоки:

- hero с названием, датой, городом, форматом и CTA;
- "О мероприятии";
- "Программа";
- "Ведущие";
- "Детали";
- финальный CTA;
- SEO-теги в `head`.

Для больших специальных лендингов можно делать индивидуальную страницу, как `events/india-tour-2026/index.html`, но URL и данные в `data/events.json` всё равно должны оставаться синхронизированными.
